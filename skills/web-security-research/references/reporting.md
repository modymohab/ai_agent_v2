# Reporting

Use this structure:

## Title

Clear description of the security issue and impact.

## Severity

Use the applicable program's severity system.

## Asset

Affected authorized asset.

## Endpoint / Functionality

Affected functionality.

## Preconditions

Required test state.

## Authentication Context

Identify the relevant test account/role.

## Description

Explain the security boundary that was violated.

## Reproduction

Provide concise reproducible steps.

## Expected Behavior

What the application should do.

## Actual Behavior

What it actually does.

## Security Impact

Describe demonstrated impact only.

## Evidence

Include relevant request/response or application-state evidence.

## Remediation

Describe the security control that should be enforced.

Do not exaggerate theoretical impact.
